WHAT CHANGED

这版计划，优化了什么

  1. 01

    从“每周”落到“每天”：24 周拆成 168 天，固定 2h / 5h / 1h 节奏，每天都有明确产出。

  2. 02

    把硬件确认前置：第 1 周先补齐抓手、负载、第二台臂与力传感器信息，避免后半程返工。

  3. 03

    每道门都带止损方案：未达标先补救，G3 不过就不硬上共同搬运。

  4. 04

    资源按使用时机标注：GPD、Contact-GraspNet 只做旁路比较，不替换稳定的解析基线。

HOW TO RUN THE WEEK

让计划能长期跑下去

A

每周固定节奏

  • 周一2h理论 + 笔记
  • 周二 · 周三4h功能开发
  • 周四2h实验 / 分析
  • 周五2h集成 / 文档
  • 周六5h仿真或真机深度工作
  • 周日1h复盘 + 休息

合计 16h/周。低于 12h/周时，按 1.5 倍周期顺延，不压缩验收实验。

B

每天最后 10 分钟

  • 今天改了哪个参数、哪份配置？
  • 指标变化了多少（成功率 / 误差 / 周期）？
  • 最大的失败样本是什么？
  • 明天唯一要验证的假设是什么？

没有写进日志的结果，默认视为没有发生。周报只从日志里摘。

C

进度落后时

  1. 先砍拓展阅读与 GPD / Contact-GraspNet 对比，保留真机实验。
  2. 单臂没通过 G3，就不开始共同搬运；双臂阶段只保留独立任务与交接。
  3. 连续两周只写代码、没有闭环实验，立即安排一次真机或仿真复盘。
  4. 指标连续两周下降，冻结新功能，只做失败样本归因。
D

开工前必须确认

  • 抓手型号、开口、指厚与通信方式
  • TCP 偏移、工具重量与重心
  • 第二台 M1013 的型号、安装位置与控制器
  • 是否有腕部六维力传感器
  • 相机固定方式、工作区边界与安全负责人

未知项先按保守假设执行，但第 1 周必须补齐；它们会直接改变月 4–6 的方案。
